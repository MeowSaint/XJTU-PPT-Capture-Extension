- `prepareMedia(file,signal,{timeoutMs=30000}={})` wraps individual Blob slice reads with an idle deadline while retaining real Blob slices and Task1's bounded parser. `AbortError` and `LOCAL_READ_FAILED`/`local-read` remain rejected promises; they are not missing-index inspection statuses. It accepts 200 or a 206 whose Content-Range is exactly 0..total-1 and whose received length matches. Content-Length is compared only without content-encoding. HTTP status, HTML/JSON, empty bodies, partial/range/length errors, interruption, timeout and cancellation are separate failures. Native fetch is aborted and late response bodies are canceled.
- [media.js](media.js) adds `PPTCore.mediaError(mediaError,{phase='load',local=false,audioOmitted=false,time=null}={}) -> Error` with `code`, `phase`, `nativeCode`, and `time`. Numeric native codes map to `MEDIA_ABORTED`, `MEDIA_NETWORK_FAILED`, `MEDIA_DECODE_FAILED`, `MEDIA_UNSUPPORTED` or `MEDIA_LOAD_FAILED`; explicit timeout is `MEDIA_TIMEOUT`. Native code 3 does not diagnose a damaged track; code 4 does not imply a stale URL. Local/cached failures advise checking the file or disk, and seek errors include source seconds.
- [scanner.js](scanner.js) accepts `constructor(video, capture, mediaContext = {})`, preserving two-argument calls and inferring local context from Blob/file URLs. Seek keeps its 30000 ms deadline and AbortSignal, clears timers/listeners even when the setter throws, and forces a real seek if loadeddata arrived without a decoded frame. Screenshot time links now use the same cancellable seek path.

When no video frame has decoded yet, a cancellable initial seek checks native frame counters and restores the start before binding. This uses no pixel-color corruption heuristic; a valid black-frame control loads. Audio-omitted results alone compare native seconds with `inspection.videoDuration` using `max(1/movieTimescale,0.001)`; original/unsupported files do not inherit that timeline guard.

[scripts/release.cjs](scripts/release.cjs), [release tests](tests/release.test.cjs), [feature harness](tests/features.cjs) and [integration harness](tests/integration.cjs) include the asset. ### Finding and change

The review's actual old-binder diagnostic observed an AbortError with persisted active lesson `new`, in-memory active lesson `old`, and retained lessons `[old,new]`. Its process exit0 meant the diagnostic completed; it was not a product pass. The independently committed lesson put and activation could not be rolled back by another late signal check.

[The persistence owner](library.js#L98) now accepts an optional AbortSignal at the existing transaction boundary. The new API `PPTLibrary.bind(db, lesson, {signal} = {}) -> Promise<void>` clones one lesson snapshot and writes both `lesson:<id>` and `activeLesson` in **one settings readwrite transaction**. A pre-aborted signal opens no transaction. Stop before commit calls the actual transaction's abort; storage errors and synchronous write exceptions leave both records unchanged.
