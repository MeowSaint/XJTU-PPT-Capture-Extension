## 验证与证据边界

最终统一修复的Node检查为278/278通过，桥接检查通过，相关浏览器检查10组通过。独立复审检查了原始输出、失败记录、生产者JSON和所有八个修改文件的当前哈希；四个运行时文件与此前桥接通过时的哈希一致，因此后续仅测试调整没有重复运行未变的桥接检查。

长任务证据来自前序任务的受控测试：1388页走实际扫描、JPEG和IndexedDB链路，视频跳转及画面使用合成适配器；2000页是预置后恢复和流式导出。它们分别证明这些受控路径，不能合称原生长视频完成采集。堆内存采样不等于RSS或进程峰值，真实事务配额回滚也不等于把物理磁盘写满。

仍有一次未解释的历史失败：连续导出最后一个JSON时，`page.waitForEvent: Timeout 10000ms exceeded while waiting for event "download"`，该命令退出1。之后重载的通过只证明恢复；较早ZIP及其中两个PDF可读，只证明较早ZIP有效。JSON缓存清理修复和新的日期测试都没有证明该超时的原因，也不能把它写成已解决。

当前环境未验证真实学校、原始坏媒体、Chrome114/Node20最低版本、原生一小时解码、物理磁盘满、RSS峰值、系统最终保存行为或课件知识完整性。首次任务部分执行只有报告中的命令和结果，后续任务和修复已保留独立stdout/stderr/退出码；两者的证据强度应保持区别。
