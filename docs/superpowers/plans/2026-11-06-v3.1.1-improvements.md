**Goal:** Finish all four groups of issues identified during the repository walkthrough, preserve existing user data and streaming exports, test the result, and deliver version 3.1.1 locally.

**Execution:** Use subagent-driven-development with one isolated implementer at a time and a fresh combined specification/quality reviewer for each task. User explicitly requested implementation and then start; routine choices below are execution rulings, not additional approval gates.

**Design:** [Scope and implementation choices](../specs/2026-11-06-v3.1.1-improvements-design.md). This document records implementation choices under the user's start authorization, not a claim of separate item-by-item approval.

**Stack:** Native JavaScript, HTML/CSS, Manifest V3, IndexedDB v3, OPFS, Node test runner, Playwright, FFmpeg, pdf-lib, Poppler. No new runtime dependencies.

## Task 1: Reliable sampling, ignore region and task-local signature cache

**Owner boundaries**
- Modify: `capture.js`, `capture.html`, `style.css`, `media.js`, `scanner.js`; `page-store.js` only if storing additional lightweight comparison metadata is necessary; `library.js` for atomic lesson/batch persistence required by review findings I1/I2.
- Tests: `tests/core.test.cjs`, `tests/scanner.test.cjs`, `tests/library.test.cjs`, `tests/library.cjs`, `tests/memory.cjs`; create `tests/improvements.cjs` as the shared browser regression suite for this release if useful.
- Read-only context: `tests/runtime.cjs`, `tests/features.cjs`, `README.md`, `tmp/scanning-recon.md`.
- Write only these files plus the assigned report and test output; do not edit version metadata or unrelated modules.

**Implementation**
1. Set the fresh/default sampling interval to 0.5 seconds while honoring explicit saved 2/8-second values. Reword the choice/help text to explain that coarse sampling can miss short slides. Avoid disrupting persisted checkpoints when merely reading an old lesson.
2. Implement one normalized ignore rectangle relative to the captured PPT area. Provide draw/clear controls, overlay feedback, persisted per-lesson state, and guard against covering the entire comparison image. Changing crop clears the ignore rectangle with feedback; changing comparison settings invalidates an old task signature so resume cannot silently reuse it.
3. Extend the existing comparison API compatibly with an optional ignore mask. Count only unmasked pixels for channel bias, changed proportion and mean difference. Store unmodified signatures and JPEGs. Centralize mask construction/comparison rather than independently reproducing the geometry in each caller.
4. Pass the same rule through scanner transition/confirmation comparison, realtime capture, global dedupe and similar-page candidate matching. Retained pages with unknown/different crop geometry must use conservative unmasked matching; optional per-page comparison metadata can make newly captured geometry explicit.
5. Reuse raw signatures during a running scan/realtime task through an awaited cache keyed by retained page ID, at most 1000 entries (82,944,000 bytes maximum for 192×108×4 signatures). Never retain image blobs. Add new signatures only after successful page commit; release on end/stop/error/source/lesson change. Failed reads remain errors and cancellation blocks subsequent commits.

**Verification**
- Add deterministic tests for default-mode A→B→A retention, masked animation with a real unmasked slide change, denominator/bias correctness, invalid/full masks, and no mutation of original signature data.
- Exercise cache reuse/read failure/invalidation in a meaningful integration test, plus persistence of ignore state and crop reset. Verify that exports retain ignored image content.
- Run `node --test tests/core.test.cjs tests/scanner.test.cjs`; run focused browser regression(s) and existing library/memory coverage when impacted. Do not loosen existing tests solely to accommodate changed defaults: set an explicit coarse interval where a fixture is actually testing the old coarse mode.
- Commit implementation and report exact commands, counts, behavior choices and limitations.

## Task 2: Safe screenshot review and navigation

**Owner boundaries**
- Modify: `capture.js`, `capture.html`, `style.css`.
- Tests: `tests/review.cjs`, `tests/library.cjs`, `tests/improvements.cjs`.
- Read-only context: `media.js`, `scanner.js`, `library.js`, `page-store.js`, `tests/runtime.cjs`.
- No storage schema or export changes; no version changes.

**Implementation**
1. Replace immediate similar-page cleanup with a dialog comparing one adjacent candidate pair at a time, using the existing similarity threshold and same-timeline/increasing-time/same-size restrictions plus Task 1 comparison rules. Show page numbers and source times with lazy image loading.
2. For each candidate offer keep earlier, keep later, keep both (safe default). Reevaluate the current survivor against the next page to handle chains without inconsistent overlapping choices. Cancellation discards all pending choices. Final confirmation invokes one existing deletion operation and one undo unit. Image URLs are released on advance/close/failure.
3. Add Shift-checkbox range selection using current display order and the latest ordinary checkbox action as anchor. Support both select and deselect. Reset invalid anchors on lesson switch/clear/delete and preserve normal keyboard operation.
4. Add a visible lightbox select toggle and `S` shortcut; add `V` for existing video seek action. Keep arrows/Delete/Esc/tab trap, ignore shortcuts in editable/form contexts, synchronize selected state with cards.
5. Add “查看截图” to saved batch rows: switch lesson and bring retained pages/suspects into view without loading the remote media. Keep busy guards.
6. Add persistent “已确认” per suspect interval. It works without a loaded video; failure keeps the interval visible. Do not accidentally resolve other overlapping/adjacent records.

**Verification**
- Browser regressions: no deletion before explicit completion; cancel unchanged; earlier/later/both decisions including A/B/C chain; one undo restores order and thumbnails; empty/no-candidate behavior.
- Shift select/deselect after reorder and invalid anchor; lightbox shortcuts and input focus; batch saved-page jump; suspect dismissal survives reload and failed persistence does not lose it.
- Adapt existing cleanup test to the deliberate confirmation workflow, preserving the behavioral assertion. Run the focused review suite and relevant regression cases, then commit and report.

## Task 3: Local library management and reusable 0-track crop

**Owner boundaries**
- Modify: `library.js`, `page-store.js`, `batch.js`, `capture.js`, `capture.html`, `style.css`.
- Tests: `tests/library.test.cjs`, `tests/library.cjs`, `tests/improvements.cjs`, `tests/features.cjs` only for affected batch expectations.
- Read-only context: `disk-cache.js`, `course.js`, `tests/runtime.cjs`.

**Implementation**
1. Add a library-management dialog listing lessons in course context, page counts and image-data byte estimates (JPEG + thumbnail + signature, not total browser disk size). Prefer optional stored byte metadata for new assets and sequential legacy reads. Do not load the entire library's images at once.
2. Add atomic lesson/course removal spanning `pages`, `assets`, `settings`, activeLesson and associated batch records. Preserve other lessons, courses and assets with legitimate retained references. Keep existing undo leases coherent; removed lesson's transient undo/preview/thumbnail state must not keep it visible or restorable.
3. Present in-product confirmation naming the lesson/course and deletion count. Do not delete without it. After successful removal release/reset the active media/selection/undo state and activate an appropriate remaining lesson or an empty state. On DB failure keep the prior state and report the error. Handle restored/rediscovered batch jobs without resurrecting deleted lesson metadata.
4. Offer crop reuse only from a confirmed 0-track crop. Explicitly explain same-camera framing and request one product confirmation for applying to other unfinished 0-track jobs in the same course. Persist normalized crop, source aspect and track identity; do not overwrite completed/manual prepared jobs without clear intent.
5. During each target load validate crop bounds, matching 0-track selection and source aspect ratio within 1%. Mismatch becomes needs-manual-crop and must never start full-frame scanning. Preserve the override and flags across task stop/failure/reload/rediscovery; allow per-job adjustments.

**Verification**
- Tests for delete single versus course, active versus inactive, cross-course isolation, assets and batch reference cleanup, injected transaction failure and empty state; legacy byte estimate and bounded image reads.
- Synthetic batch tests for confirmed reuse, equal-aspect differing resolution, changed aspect/track rejection, completed/other-course exclusion, refresh and manual adjustment.
- Run relevant Node and browser library/batch tests, commit, and report exact counts.

## Task 4: Selected-page exports, PDF navigation and batch course download

**Owner boundaries**
- Modify: `pdf.js`, `capture.js`, `capture.html`, `style.css`.
- Tests: `tests/export.test.cjs`, `tests/improvements.cjs`, `tests/integration.cjs`, `tests/features.cjs` only when related.
- Read-only context: `course.js`, `library.js`, `tests/runtime.cjs`, `scripts/release.cjs` if needed to verify packaging file names.

**Interfaces and implementation**
1. Extend `makePDF(pages, options = {})`, `writePDF(pages, options)` and `writeCourseZIP(lessons, options)` with boolean `timestamps` and `bookmarks`, both false by default; existing callers and default PDF bytes remain compatible.
2. Timestamp labels use finite nonnegative `sourceTime` formatted `HH:MM:SS`; unavailable times produce no fake label. Single layout adds image-external footer space; handout labels sit with the associated slide number. Keep JPEG bytes untouched and dimensions correct.
3. Add PDF outlines with ASCII page number/time titles and correct destination PDF page/vertical position, including two-slide handouts and odd final pages. No font dependency or internal implementation jargon in the user controls.
4. Persist PDF setting controls consistently with existing export settings and pass to every PDF export path, including per-job, selected-page, main course ZIP and batch course ZIP.
5. Add explicit selected PDF / selected image ZIP actions. Snapshot selected metadata in display order at start; require at least one selection; filename includes `-selected`. Existing all-retained export stays all-retained regardless of selection.
6. Add batch-panel course-PDF ZIP shortcut that reuses a shared export implementation with an explicit course key derived from the displayed batch page, independent of the active lesson. Keep unavailable/empty/incomplete messaging and busy guards.

**Verification**
- Node/pdf-lib tests: timestamp present/absent, invalid time, PDF outlines/destinations/counts, single/handout, odd count, exported order, options propagated into course members, unchanged default bytes, asynchronous backpressure and bounded image reads.
- Browser tests: one/many/zero selections, selected versus all behavior, selected filenames, restored option controls, batch course scope when another course is active.
- Render representative single/handout PDFs via existing Poppler tooling to inspect page geometry. Run PDF tests and affected integration/browser cases, then commit and report.
